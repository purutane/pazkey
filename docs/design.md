# 設計の全体像

pazkey は、azooKey と Zenzai をそのまま使い、fcitx5 アドオンと変換サーバーを作った日本語入力である。最優先は「サーバーがどうなっていても、文字入力は止めない」である。

## 設計原則

1. **入力を止めない。** fcitx5 のメインスレッドはサーバーを待たない。変換は非同期で行い、期限を過ぎたらひらがなとカタカナで代用する。
2. **入力中の状態はフロントエンドが持つ。** サーバーが落ちても、入力中の文字は消えない。
3. **同じ学習状態なら、同じ要求には同じ結果を返す。** 変換の要求には、読み、カーソル位置、文脈をすべて載せる。サーバー側のセッションは高速化用のキャッシュにすぎず、消えても結果は変わらない。結果が変わるのは学習が入ったときだけで、保存する前に落ちれば、その分の学習は失われる（「障害時の振る舞い」）。
4. **アプリに送るのは、中身のある変更だけ。** 空の commit や、変化のない preedit の更新は送らない。
5. **プロセスの管理は systemd に任せる。** 起動、再起動、接続の受け付けを自前で書かない。
6. **azooKey はリファレンス実装と同じ順序で呼ぶ。** `AncoSession` を手本にする。
7. **機能を絞る。** 入力はローマ字だけ。設定画面は fcitx5 の設定機構に任せ、自前の画面は作らない。変換の機能は azooKey が提供するものに乗り、自分では作り込まない（特殊な変換は azooKey の既定をそのまま使う。`docs/server.md`「変換のオプション」）。キー操作や字種などの入力の振る舞いは Mozc の既定に合わせ、設定で切り替えられるようにはしない。ただし、あとで切り替えられる設計にしておく（Mozc の設定と同じ名前と選択肢の形で、既定値を決め打ちにして1か所に置く。`docs/frontend.md`「Mozc の設定との対応」）。

## 構成

```
 アプリの入力欄
    │ キー入力      ▲ preedit、確定文字列
    ▼              │
┌──────────────────────────┐   UNIX ソケット    ┌──────────────────────────┐
│ fcitx5 アドオン（C++）     │   JSON を1行ずつ   │ 変換サーバー（Swift）      │
│                          │ ── convert ─────▶ │                          │
│ ・入力状態（読み・カーソル）│ ── commit ──────▶ │ ・受付スレッド             │
│ ・ローマ字かな変換         │ ◀──── result ──── │ ・直列キュー + azooKey     │
│ ・render(state)          │ ◀ config_changed ─ │ ・学習（その場で反映、定期保存）│
│ ・非同期クライアント       │                   │ ・設定ファイルの監視        │
└──────────────────────────┘                   └──────────────────────────┘
                                                       ▲ 起動・再起動
                                               ┌───────┴──────────┐
                                               │ systemd          │
                                               │ .socket / .service│
                                               └──────────────────┘
```

| 部分 | 言語 | 担うこと | 仕様 |
|---|---|---|---|
| fcitx5 アドオン | C++ | キー処理、ローマ字かな変換、入力状態、画面への反映、設定画面の項目 | `docs/frontend.md` |
| 変換サーバー | Swift | azooKey の呼び出し、セッション管理、学習、設定ファイルの監視 | `docs/server.md` |
| プロトコル | JSON | 両者の間のメッセージ | `docs/protocol.md` |
| 設定 | JSON | 設定項目、検証、反映 | `docs/config.md` |
| CLI | Swift | `pazkey-ctl reload` / `devices` / `status` / `debug` / `fetch-model` | `docs/server.md` |
| systemd ユニット | - | ソケット起動、再起動 | `docs/server.md` |

## 障害時の振る舞い

どの障害が起きても、失うのは「変換の質」か「学習の1回分」までにとどめる。

| 起きること | 振る舞い |
|---|---|
| サーバーが落ちる | systemd が再起動する。入力中の文字はフロントエンドに残る。応答がなければ仮名で代用する |
| サーバーが応答しない | 期限を過ぎたら代用する。入力は止まらない |
| 短時間に何度も落ちる | Zenzai を切って起動し直す退避モードに入る |
| 再起動中に接続が来る | systemd のソケット起動なので、カーネルが接続を待たせておく |
| 設定ファイルが不正 | 直前の正しい設定で動き続け、通知する |
| 学習データが壊れる | azooKey の処理で破棄される |

## 作らないもの

自前の設定画面（Qt）、AZIK とかな入力、キーマップの編集画面、Flatpak 対応。

- 英数の直接入力モード、全角英数の入力モード。英数は fcitx5 の入力メソッドの切り替えで入力する。入力中の読みを F9 / F10 で全角 / 半角の英数字にして表示する機能（Mozc と同じ）は作る（`docs/frontend.md`「キーごとの動作」）。Shift で英字を打ってから確定するまでの一時的な半角英字の入力（Mozc と同じ）は作る（`docs/frontend.md`「字種」）。切り替えて使い続けるモードは作らない。
- azooKey が提供しない変換機能の作り込み（独自の特殊な変換など）。
- systemd のユーザーセッションがない環境（OpenRC、runit などで動く Artix、Void など）への対応。そうした環境では、`pazkey-server --listen "$XDG_RUNTIME_DIR/pazkey/server.sock"` を自分で起動しておけば動くが、再起動などの面倒は見ない。
